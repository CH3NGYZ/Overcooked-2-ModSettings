## 已实现

- 修改按键的中文统一为“改键”。KeyCode保留值下拉＋改键＋默认，KeyboardShortcut分开显示当前组合与改键按钮，仍走已有捕获弹层。
- 使用实际T17Text字形测量，将名称列设为24%/32%/40%/49%中可容纳的最小档；超过49%换行，按文字高度增加本行高度，名称不缩字。
- 名称与操作区间隔整行2%；操作区内部间隔为操作区总宽2%。开关、改键、恢复默认和范围精确输入宽度统一为操作区24%；弹性文本/下拉/滑条填满其余空间，向量分量均分余量。隐藏默认按钮不留占位。
- 按钮最小字号12，开关图标保持原64×64 UI。颜色目前沿用RGBA交互，仅跟随列宽与输入框皮肤，后续交互方案待选择。
- 搜索和所有输入框复用与下拉/按钮相同的原生背景资源，使用明亮文字、浅红非法输入、浅蓝全选状态，保留原有即时保存和IME生命周期。

- 后续独立跨场景补跑92项通过，上述载入后退出未再复现，仍不声称找到了退出原因。当前未验证物理键鼠/手柄/IME、Steam联机、其他分辨率、全部共享副本组合或第三方重型renderer。游戏和其他MOD仍有既有告警，不声称零错误环境。

## 颜色可选方案（当时尚未实施，后已选第一项）

| 方案 | 交互与取舍 |
|---|---|
| 色板弹层（推荐） | 行内只留Hex、最终颜色预览和选色入口；打开后用二维饱和度/明度色板＋彩虹色相条＋A透明度条。最节省设置列表高度，支持全色域，但多一次打开操作。 |
| 行内紧凑HSV | 色相条同行配Hex和预览，第二行并排S/V，第三行A；都能原地调节，行高比四条RGBA加底栏小，操作元素更多。 |
| 精确RGBA | 维持四通道滑条和数值，用统一档位压缩排布；适合照数值配置，最接近目前行为，直觉选色效率较低。 |

以上都保留Hex、透明棋盘预览和拖动联动，复用既有松手提交/取消回读流程。只有彩虹条＋A不够：色相只有一个自由度，不能同时覆盖灰度、饱和度与明暗，需要S/V或二维色板补齐。
